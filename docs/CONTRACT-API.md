## OrderVault

- Source: `packages/foundry/contracts/OrderVault.sol`
- Inherits `Ownable2Step`, `ReentrancyGuard`
- Hedera testnet: [`0xc265045c65d0114109072d60b3a60231427a06a9`](https://hashscan.io/testnet/contract/0xc265045c65d0114109072d60b3a60231427a06a9)

Limit and stop orders that execute on SaucerSwap V2 with no off-chain keeper.

Each order is an HTS NFT minted by this vault; whoever holds it owns the order. Each market runs one self-rescheduling sweep through the Hedera Schedule Service, and the sweep's cost is split across the orders it checks. Scheduling a call is a fixed network fee, so the next sweep waits as long as the nearest trigger allows. A fill needs the pool's TWAP to agree with Chainlink, so a manipulated or stale market cannot drain an order.

#### `sweep`

```solidity
function sweep(uint256 marketId, uint32 epoch) external nonReentrant
```

Check up to `maxOrders` open orders of a market, fill the ones whose trigger is met, and, when called by the Hedera Schedule Service, schedule the next sweep.

- Access: Anyone. The Hedera Schedule Service calls it as the vault itself (a scheduled sweep).
- Mutability: `nonpayable`
- Selector: `0x4ebfac46` (`sweep(uint256,uint32)`)

Scheduled calls arrive with msg.sender == this vault and carry the epoch they were scheduled under; a stale epoch means an earlier sweep replaced this one, so it returns at once. Scheduled calls debit each checked order's budget because the vault pays their fees. Manual calls are paid by the caller, debit nothing and ignore `epoch`. A manual call schedules the next sweep only when the chain is dead (see `restartSweep`).

| Parameter | Type | Description |
| --- | --- | --- |
| `marketId` | `uint256` | A listed market. |
| `epoch` | `uint32` | The epoch a scheduled call was created under; manual calls may pass any value. |

Reverts:

- [`UnknownMarket`](#unknownmarket) if the market is not listed.

## OrderVaultLens

- Source: `packages/foundry/contracts/OrderVaultLens.sol`
- Hedera testnet: [`0x71bef6696d1c684f2f9d1581f4adb07e9d7e9d8e`](https://hashscan.io/testnet/contract/0x71bef6696d1c684f2f9d1581f4adb07e9d7e9d8e)

Read-only previews of what an `OrderVault` will charge and when it will check, for the frontend and the Debug page. It holds no state and no funds; every figure is computed from the vault's raw state with `SweepMath`, the same code the vault charges and schedules by, so a preview and the vault's own number cannot drift apart. Kept out of the vault so the vault stays well under the 24 KB limit.

## TrailingStopType

- Source: `packages/foundry/contracts/ordertypes/TrailingStopType.sol`
- Implements [`IOrderType`](#iordertype)
- Hedera testnet: [`0x2e449f0ed73d54239b9cd647d0a23ab1d9c78a36`](https://hashscan.io/testnet/contract/0x2e449f0ed73d54239b9cd647d0a23ab1d9c78a36)

Rides the price up and fires on a pullback: it tracks the highest Chainlink price the order has seen at a check (the "peak"), and the trigger is `peak × (1 − trail)`. As the peak rises the trigger rises with it; it never moves down.

The peak is the maximum of the oracle **sampled at scheduled checks**, not the true continuous high, so a spike that reverses entirely between two checks is not captured. This is inherent to a pay-per-check, on-chain design and is stated in the UI and docs. Per-order state is the peak, returned to the vault which stores it; this contract is pure and cannot itself write anything. `script/Deploy.s.sol` registers it as order type 2.

## IOrderType

- Source: `packages/foundry/contracts/interfaces/IOrderType.sol`
- Interface
- Implemented by [`LimitOrderType`](#limitordertype), [`StopOrderType`](#stopordertype), [`TrailingStopType`](#trailingstoptype)

A stateless, view-only strategy for one kind of order (limit, stop-loss, trailing stop, …). The vault owns all order state and all funds; a strategy only reads what the vault passes and returns decisions.
